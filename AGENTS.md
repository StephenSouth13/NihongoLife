# NihongoLife repository rules

Read this before changing anything. These rules come from bugs that already happened; each one has a test that
guards it. Keep code that works — fix what is wrong, do not rewrite a working system to your own taste.

## Scenes, assets, builders

- Do not add Unity editor commands with `[MenuItem]`. Build, setup, asset integration and scene repair must not require manual menu actions. Builders run headless: `Unity -batchmode -executeMethod <Class.Method>`.
- Do not create another Unity scene unless the user explicitly approves that exact scene. Prefer improving the existing gameplay scene and reusable prefabs.
- Persist finished content directly in scenes, prefabs and assets. Opening the project and pressing Play must use the finished state without a setup step.
- Never stack a replacement environment on top of an existing one. Remove or disable the superseded hierarchy, then validate renderers, colliders, doors, spawn points and navigation together.
- Do not claim a scene is complete without Play Mode visual and collision testing.
- Generated content is rebuilt by its builder, never hand-edited in the scene: streets `CityStreetBuilder.Build` (90_TestSandbox; `NL_STREET_SCENE=01_MainMenu` for the menu's copy of the town), town entrances `CityTownBuilder`, Game Center `GameCenterBuilder`, UFO catcher art `Tools/art/ufo_catcher_art.py`, story quests `Tools/story/*.py`.

## Product rules (decided by the owner — do not change without asking)

- **Guest / offline = the whole town open.** A guest (no account signed in, `PlayerSessionService.Mode == Guest`) has every place unlocked and is not held in the opening story. This is derived from the session (`PlayerSessionService.OpenWorld`), never from which menu button was pressed — starting the town directly must behave the same. Do not set `LocationUnlocks.Bypass` / `StoryDirector.Bypass` in game code; those flags are for tests only.
- **Account = campaign + online.** A signed-in registered account plays the roadmap (places open by 「trí tuệ」 knowledge + story quests, `LocationUnlocks`) and may go online. Online features (online world, friends, chat, co-op, voice, Speaking room, island visits, ranking submissions) require `OnlineAccess.IsRegistered` (signed in with an email). Guests are invited to register (`AuthUI.ShowForOnline`).
- Guest progress is saved on the device (`guest_progress.json`) and moves into a **new** account on its first sign-in; an existing account keeps its own save.
- **Each account has its own local save** (`progress_<userId>.json`, `PlayerSessionService.AccountId`). On a shared machine one account must never start from — or merge into the cloud — another account's save. Repositories reload when the session's account changes.
- The server enforces "registered only" too: Edge Functions reject anonymous users (`user.is_anonymous`), private voice calls are issued only to their two players (`agora-voice` checks `peer`), and the database uses `public.is_registered()` for online writes. Never rely on the client alone.
- The Vietnamese UI word for knowledge is **trí tuệ** (not "kiến thức").
- The game has exactly three founders: Quách Thành Long, Nguyễn Lê Gia Huy, Lương Nguyễn Tấn Dũng (`Resources/Menu/menu_about.asset`). Do not add other names to the founder credits.
- Priorities: online communication and the IELTS / JLPT exams, on the website (WebGL) as well as desktop.

## Invariants (each one broke once)

- **Never move a component's own transform for a side effect.** An `AudioSource` / FX that must follow something lives on its own child GameObject. (StreetTraffic once put its horn on the Traffic root and moved it to the honking car — every car jumped onto pavements and roofs.)
- **Unity fake null**: never write `GetComponent<T>() ?? …` (or `?.` on a Unity object you just looked up) — in the Editor a missing component is a fake-null object, so `??` never runs and the next access throws `MissingComponentException`. Write `GetComponent<T>().OrNull() ?? …` (`Scripts/Core/UnityNull.cs`) or an explicit `== null` check.
- **Modal entries** (`UiModalStack.Register`): the `isOpen` callback must mean "visible on screen now" (`activeInHierarchy`), not "the object exists". A hidden-but-alive card that still reports open blocks Esc, the map-unlock card and every "no overlay" check.
- **Input**: per-frame code must not clear shared input it does not own. The touch overlay releases its joystick/buttons once when it hides, never every frame while hidden (that wiped the mobile move and buttons for everything else).
- **Town edge** (`World/TownEdge.cs`): only the city scene has an edge; zones (island, station, shops) must never be treated as the town, and F near the edge only travels while the city is the active scene — otherwise F at counters / fishing spots / NPCs travels to the station.
- **Expressions** (`Player/KidExpression.cs`): mood gestures (bow / point) only play while the character is free — not sleeping, fainted, sitting, working or in dialogue.
- **Traffic** (`World/StreetTraffic.cs`): the Traffic root never moves; cars move only along local X in their lane (eastbound z −8.4, westbound z −11.6); kinematic cars must never push the player's CharacterController — `SeparateFromPlayer` sets the player beside the car on the kerb side; the bumper (not the pivot) stops behind the stop line; cars brake with `Braking()`. Tests: `TrafficLanePlayModeTests`, `StreetTrafficPlayModeTests`.
- **Streets** (`Editor/CityStreetBuilder*.cs`): zebra bars run along the road; stop lines 2 m before the zebra; walls are clipped against every building and reserved area (`c.solids`) and a lot that still overlaps a reserved area (konbini, plaza, station) is dropped. Test: `StreetTrafficPlayModeTests` (no yard wall inside the konbini).
- **Lighting**: `PC_RPAsset` shadow depth bias 1 / normal bias 1 (0.1 caused shadow acne — the ground flashed dark); thin ground layers and `GameplayGround` do not cast shadows. Test: `LightingFlickerPlayModeTests`.
- **Camera** (`ThirdPersonCameraController`): orbit angles apply at once, only the pivot is smoothed, distance pulls in at once and eases out; overhead canopies / sign boards have colliders so the camera never passes through them.
- **Per-frame cost**: no `FindObjectsByType` / `GetComponent(s)InChildren` / allocations every frame in `Update` / `LateUpdate` — scan on a timer (0.2–1 s) or on change; use `SceneRefs.Find` for cached singletons. The web and mobile builds feel every one of them.
- **WebGL**: with the build target set to WebGL the Editor compiles the web path (`#if UNITY_WEBGL`), so keep `Agora.Rtc` shim code fully qualified (`NihongoLife.Learning.…`) and compile once with the WebGL target before pushing web changes. Excluded from WebGL: `AgoraRtcSDK.asmdef` (excludePlatforms); the web path is `AgoraWebShim` / `VideoSurface` / `NihongoAgora.jslib`; `UnityEngine.Microphone` does not exist on WebGL (`Exam/WebMicrophone.cs`); no threads or `ClientWebSocket` on WebGL (`NihongoRealtime.jslib`); saves flush IndexedDB (`NihongoLifeWeb.jslib`). Check the web compile with the build target set to WebGL (`Unity -batchmode -quit -buildTarget WebGL -projectPath …`, zero `error CS`).
- **Health** (`Player/PlayerStatus.cs`, `StatusConsequences.cs`): health heals by itself while food and water are ≥ 30 % (not at 0 — at 0 you faint first), a meal heals at once, 8 h of sleep heals fully. A blackout cut short (scene change, disabled player) must reset (`OnDisable`) and give control back; health still at 0 faints again. Test: `NeedsWeatherPlayModeTests.Health_HealsWhenFed_AndAStuckFaintRecovers`.
- **Intro trailer** (`Core/IntroTrailer.cs`, `TrailerReel`): it films the real town on an in-memory save (`IntroTrailer.Playing` pauses needs and fainting); the player's save is never read or written by it. A guest's first game plays it once (skip: button / Esc / Enter / Space). Tests set `IntroTrailer.Bypass`. Test: `IntroTrailerPlayModeTests`.
- **Station gates** (`World/TicketGate.cs`, `Editor/StationGateBuilder.cs`): the gates are the only way between hall and platform (railing either side); a ticket opens the lane, the platform side always opens. Scenery on the tracks (parked trains) has no colliders. Test: `StationGatePlayModeTests` walks it with the real CharacterController.
- **Careers** (`Progression/CareerService.cs`, `Resources/Progression/careers.json`, `UI/CareerUI.cs`): unlock at level 10 for guests and accounts; the work is the existing part-time shift (`shiftQuest`), a career only adds salary, title, performance, a Japanese promotion interview, a branch at level 4 and work events. New careers / levels / interviews / events are JSON only; `CareerCatalogTests` validates the file. Tests: `CareerPlayModeTests` (`CareerClock.PromptEnabled` is off in other tests).
- **Hibari Clinic** (`35_HibariClinic`, `Editor/ClinicBuilder.cs`, `Clinic/ClinicVisit.cs`, `Resources/Clinic/clinic.json`): patient visit (受付 → 問診票 → 診察 → 会計 → お薬) heals fully; the clinic task line is category `clinic` in progression.json; the clinic shift (`job_clinic_shift`) is the Medical career's work; fainting wakes the player on the recovery bed (spawn `clinic_bed`). Indoor zones keep their own light with `Core/IndoorAmbience` (the town's sky would otherwise darken them at night). Test: `ClinicPlayModeTests`.
- **Character look** (`Player/CharacterLook.cs`): hair is recoloured through the baked mask (`CharacterLookBuilder.Build` → `Resources/Characters/Looks/looks.json` + `hairmask_*`, generated — rebuild, never edit); beards / wrinkles live on their own child `Look_Face` of the head bone; options and the age pace are `look_options.json`. Tests never write the device look (`CharacterLook.Persist = false`). Test: `CharacterLookPlayModeTests`.
- **Clinic townspeople** (`Clinic/ClinicPatientFlow.cs`): no colliders, one person in the consultation room at a time, route points from `ClinicBuilder` ("PatientRoute"); `ClinicBuilder.BuildInterior` rebuilds only the clinic scene. Test: `ClinicPlayModeTests.Clinic_TownspeopleComeForACheckUp`.
- **Illness** (`Health/PlayerIllness.cs`, `Resources/Health/illnesses.json`): treatment must stay true to real practice (sources in `Docs/HEALTH_SOURCES.md`) — over-the-counter medicine relieves, it does not cure; antibiotics never treat colds or flu; flu antivirals work best in the first 48 h. Tests keep `PlayerIllness.Triggers = false` unless they test catching. Tests: `IllnessCatalogTests`, `IllnessPlayModeTests`.
- **Handbook** (`UI/HandbookUI.cs`, key Y): the map's place guide (`LocationGuideUI`) is its 場所 chapter; content comes from JSON (handbook.json, locations.json, illnesses.json, careers.json, music.json). Original music is rebuilt by `Tools/audio/compose_music.py`.
- **Phú Quốc** (restarted by the owner 27/10/2026): `65_PhuQuocIsland` is built only by `PhuQuocIslandBuilder.Build` from `Resources/PhuQuoc/phu_quoc_map.json` (real OpenStreetMap coordinates, 1 unit = 100 m — never 1:1 for the whole island); the hospitality career works at Gánh Ngon (`ganh_ngon.json`, `GanhNgonShift`). A MonoBehaviour placed in a scene must live in a file of its own name (`GanhNgonSpot.cs`), or the scene loses it. Other expansions not in the game yet live under `NihongoLife/Docs/Expansion/`; do not register their scenes until the owner restarts them. Tests: `PhuQuocRestaurantTests`, `PhuQuocIslandPlayModeTests`.
- **Hibiki Music & Art** (`55_MusicShop`, approved by the owner 29/10/2026; `Editor/MusicShopBuilder.cs`): the gallery is a real 3D room — every painting of `Resources/Art/artworks.json` hangs on a wall (quad, not a cube: a cube face flips the picture), the 2D gallery tab is only a catalogue. Gallery pictures keep their size (`ArtImagePostprocessor`, nPOTScale None). Music is mainly the character playing by itself (`MusicStudioUI.AutoPlay`: tempo, volume, instrument, loop; seated at an instrument the window shrinks to a bar so the character stays visible); playing by hand on the keyboard stays. A stage show counts when the tempo is 80–125 %. Careers musician / producer / painter are JSON (`Tools/music/add_arts_careers.py`). Tests: `MusicShopPlayModeTests`, `MusicStudioPlayModeTests`, `MusicCatalogTests`.
- **Gestures** (`Gestures/GestureLayer.cs`): a gesture ends when the body "walks away" (speed > 0.7 m/s between frames). Never reset that measure inside `Play`/`Begin` — callers replay gestures often, the walk check then never fires and a gesture sticks over the walk (the player slid without stepping or turning). Call `ResetMotion()` only right after placing a body (seated at an instrument). Tests: `FootGroundingPlayModeTests`, `FootSlipPlayModeTests` in the full run.
- **Station passengers** (`World/PlatformCrowd.cs`): heights come from the floor under them (raycast), never from the train door (its pivot is the door's middle). Test: `PlatformCrowdPlayModeTests`.
- **One MonoBehaviour per file, named like the file.** A component placed in a scene or prefab whose class sits in another file (e.g. `ClinicSpot` in `ClinicVisit.cs`) is saved without a GUID: on load it is a missing script and silently does nothing. `ZoneConsolePlayModeTests` enters the islands and the clinic and fails on any missing script or console error.
- **A new zone** must be registered like the others: `WorldLocationCatalog` (scene + spawn id), `StandaloneZoneBootstrap` (Play inside the zone boots the town), a `SceneZoneVisibility` root far from the town, a `SceneSpawnPoint`, a `ScenePortal` back, a `ZonePreviewCamera` — no camera or sun of its own.
- **Zones share the town scene's player**: anything in the city scene that reacts to the player (TownEdge, ambience) must also check the city is the active scene — zones sit far outside the town's bounds.
- **WebGL shaders**: no shader may sample the shadow map unless a shadow keyword is on. The kids' toon graph (`ThirdParty/New Chac/.../CustonLight.hlsl`) did, and the browser refused the draw ("Mismatch between texture format and sampler type") — characters vanished on the web only.
- **Web audio**: music (`Audio/Music`) and story voices (`Voice/`) leave the web build's first download (`Editor/WebAudioOnDemand`, called by `ReleaseBuild.BuildWebGL`) and load through `Audio/WebAudioStore.Get` / `IsPending`. Never `Resources.Load<AudioClip>` them directly. The parking folder `Assets/NihongoLife/WebOnDemand` exists only during a web build.
- **Loading a save never faints the player** (`PlayerStatus.WakeSafely`): a save written while starving or at 0 health starts awake and fed enough to heal.
- **Web scene loads** (`Core/SceneContentLoader.CanLoad`): on WebGL every area is an AssetBundle in `zones/`, so `Application.CanStreamedLevelBeLoaded` is false until it is downloaded. Never gate a scene load on that alone — "Play" and every door did nothing in the browser.
- **Web online settings**: a browser cannot read `LocalSecrets/secrets.json`. The WebGL build writes `nl-config.js` beside index.html (`WebGLZoneBundleBuilder.WriteWebConfig`, public values only: Supabase URL + anon key, Agora App ID; a secret key fails the build; never the Gemini key) and `LocalSecrets` reads it through `NL_GetWebConfig`.
- **Carried and worn things** (`Gestures/CarryHold`, gestures.json): a dish (`carry_tray`), a box, the player's guitar on the back (`carry_guitar`) are gesture props, so they sit in the hands / on the body of any rig. Body-worn props are anchored to the hips (`hand: "H"`), never at an adult's height in the world (a kid's head hid the guitar; a 1.05 m disc floated at a kid's face).
- **Guitar props** (`guitar`, `guitar_back` in gestures.json): generated by `Tools/music/guitar_props.py` along one neck axis — never hand-edit the pieces (a neck sloping one way and a headstock the other looked broken apart). Test: `AllCharactersPlayPlayModeTests` (every character walks and plays; no guitar piece floats apart).
- **Phones**: landscape only (Android: `ReleaseBuild.BuildAndroid` + ProjectSettings; web: the template's full-screen "turn your phone" card, which locks landscape where the browser allows and never traps — "keep playing in portrait"). The on-screen controls are `TouchControlPrefs.Mode` (Auto / On / Off), switchable from Settings and from the main menu (`ControlsButton`). Test: `PhoneControlsPlayModeTests`.
- **Classroom seats** (`Editor/ClassroomBuilder.MeasureSeat`): the bench is read from the chair-table mesh, never guessed (students sat inside the desks). Test: `PlacesLookPlayModeTests`.
- **Bank** (`Bank/BankService`, `Resources/Bank/bank.json`): a broke player always has the interest-free emergency fund; a late loan never seizes things or drives the wallet below 0, keeps back at most `garnishPercent` of an income, and can be extended once free. An unpaid clinic fee becomes an interest-free bill. Tests: `BankCatalogTests`, `BankPlayModeTests`.
- **Train views** (`World/TrainWindowScenery`, `Editor/StationTrainBuilder.Route.cs`): each stop has its own surroundings, swapped inside a tunnel mid-leg; the platform with the name board slides in to stop at the window. A new stop in `StationTravelController.Line` needs its view and is shown on the hall's route board (`StationGuideBuilder`). Test: `TrainRoutePlayModeTests`.
- **Text files are UTF-8.** Data written through a non-UTF-8 code page turns accents, kana and Cyrillic into `?` (it happened to `career_industries.json` and `variants.json`). Write JSON with `ensure_ascii=False` and `encoding='utf-8'`.
- Never write secrets (Supabase service keys, DB passwords, API keys) into files or commits. Cambridge / JLPT source materials stay local-only.

## Testing

- Unity can open the project once: batch runs fail while the Editor is open. Close it, then: `Unity -batchmode -projectPath <project> -runTests -testPlatform PlayMode|EditMode -testFilter "A|B" -testResults <xml> -logFile <log>`. Put logs on drive D (C: is full).
- `PlayModeSaveGuard` protects the real save and sets test defaults: `LocationUnlocks.Bypass = true`, `StoryDirector.Bypass = true`, `PlayerSessionService.PersistGuest = false`, `PlayerSessionService.GuestFullAccess = false`. A test that checks gates turns the bypass off and restores it in `finally` / `TearDown`.
- Known external / flaky: `IeltsProductivePlayModeTests` real-AI cases (network), `WeatherCameraPlayerPlayModeTests` rain recovery, occasionally `SpeakingLive` / `MidoriIsland` (re-run alone).
- Prove visual work with captures under `Bao_Cao/<topic>/` and look at them before reporting.

## Teamwork

- Before changing a system, read `NihongoLife/Docs/TEAM_TASKS.md` and the system's tests. After a change, add a short dated entry to `TEAM_TASKS.md` (what, why, files, tests).
- Keep commits focused, with the test that proves them; run the related tests and the full suite before pushing to `main`.
